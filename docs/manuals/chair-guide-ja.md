# IWSO 2027 — Chair(運営)向けマニュアル

トラック設定・査読者アサイン・採否確定・通知・プログラム作成まで、運営業務全体の流れを説明します。

## 1. サインイン方法

他のロールと同じ方法でサインインします。サインインページでメールアドレスを入力し、届いたメール内のリンクをクリックしてください。Chairロールを持つアカウントには、上部メニューに **Admin** リンクが表示されます。

## 2. Admin Overview(`/admin`)

投稿総数、ステータス別内訳(Draft / Submitted / Under Review / Decided / Withdrawn)、トラック数、査読者数を確認できるダッシュボードです。状況を一目で確認するためのもので、特に操作は必要ありません。

## 3. 事前設定

投稿受付を開始する前に、以下を設定しておいてください。

### Tracks(トラック、`/admin/tracks`)
投稿者が投稿時に選択するトピック分野を作成します(名前・短いコード・説明(任意))。トラックは以下の用途にも使われます。

- **査読者の専門分野マッチング** — 自動割当時に、投稿のトラックと専門分野が一致する査読者を優先します。
- 投稿が紐づいているトラックは削除できません。先に該当投稿を削除するか、別のトラックに変更してください。

### Conference Settings(会議設定、`/admin/settings`)
- 会議名、タイムゾーン
- 投稿締切・査読締切・通知予定日(トップページに表示されます)
- **General Talk Duration**(一般発表時間)・**Invited Talk Duration**(招待発表時間)(分単位)— プログラム作成時の発表時刻自動計算に使用されます(7章参照)

### Users(ユーザー管理、`/admin/users`)
- **Invite User** — メールアドレスを指定してReviewer・Chairロールを付与します。付与後はそのメールアドレスですぐにサインインできますが、招待メールは自動送信されないため、本人には別途直接お知らせください。
- 既存ユーザー(一度でもサインインしたことがある全ユーザー、投稿者も含む)について、**Reviewer**・**Chair** ロールのON/OFFを切り替えられます。
- 査読者には **Expertise**(専門分野)としてトラックを設定でき、自動割当時に使用されます。
- 自分自身のChairロールは外せません(誤って自分をロックアウトしないための保護です)。

## 4. 投稿の管理(`/admin/submissions`)

投稿の全件一覧で、ステータスで絞り込めます。各投稿を開くと以下が確認できます。

- Abstract(PDF)、キーワード、著者情報
- 全査読者のスコア・推奨(Accept/Reject)・コメント(自分(Chair)にのみ表示される非公開コメントも含む)
- 提出済み査読の平均スコア
- **Program** — その投稿の **発表カテゴリ**(General または Invited)を設定します。プログラム作成時の発表時間の長さに反映されます(7章)。それ以外には影響しません。
- **Decision** — **Accept** または **Reject** をクリックして採否を確定します。ステータスが **Decided** になります。この時点では投稿者への通知はまだ送信されません。送信はDecisionsページから行います(6章)。
- **Danger zone → Delete submission** — 投稿およびそれに紐づく全データ(Abstractファイル・著者情報・査読アサイン・査読結果)を完全に削除します。テスト投稿や重複投稿の削除に使用してください。元に戻せません。

## 5. 査読者のアサイン(`/admin/assignments`)

Submitted・Under Reviewの投稿と、その現在の査読者一覧が表示されます。

- **手動アサイン** — 投稿ごとにプルダウンから査読者を選択してアサインします。その投稿の著者・投稿者本人は選択肢から自動的に除外されます。
- **Auto Assign**(自動割当) — 査読者が不足している(デフォルトでは1件あたり2名)全投稿に対し、専門分野が一致する査読者を優先し、査読者間の負荷を分散しながら自動的にアサインします。利益相反(COI)は自動的に除外されます。
- **Remove** — 投稿から査読者のアサインを解除します。
- **Send Reminders** — 未提出(Pending)の査読がある査読者全員に、アサインごとに1通ずつリマインダーメールを送信します。

### Pending Reviewer Notifications(通知未送信の一覧)

査読者のアサイン(手動・自動どちらも)は、**その場ではメールを送信しません**。代わりにこのセクションに査読者ごとにまとめて表示されます。同じタイミングで複数件アサインされた査読者には、1件ずつではなく、まとめて1通のメールが送られます。

- 査読者の横の **Send** をクリックすると、その査読者にのみ通知を送ります。
- **Send All Pending (N)** をクリックすると、未通知の全員にまとめて通知を送ります。

一度アサイン解除した査読者を同じ投稿に再アサインした場合、過去の通知履歴に関係なく再度「未通知」扱いになるため、改めて送信が必要です。

## 6. 採否の確定と通知(`/admin/decisions`)

**Decided**(4章で採否確定済み)の投稿が一覧表示されます。

- 各行には、その投稿者へすでに通知済みかどうか、およびメールに含まれる査読者コメント(著者向け)の件数が表示されます。
- **Send** — その投稿の著者へ、採否結果のメールを送信します。
- **Send All Pending (N)** — 未通知の投稿者全員にまとめて送信します。

通知メールには採否結果と、「著者向け」とマークされた査読コメントが含まれます。Chair宛の非公開コメントは一切含まれません。

## 7. プログラムの作成(`/admin/program`)

採択(Accept)確定済みの投稿のみ、プログラムに追加できます。

1. **New Session** — タイトル・種別(Oral Session / Poster Session / Keynote / Break)・会場・トラック(任意)・開始/終了時刻を指定してセッションを作成します。
2. 各セッションの検索欄で、未割当の採択投稿をキーワードまたはタイトルで絞り込み、選択して **Add** をクリックします。
   - その投稿の著者が、時間の重なる別セッションに既にアサインされている場合は警告が表示されます(ただし警告が出てもアサイン自体は実行されるため、最終判断はChairに委ねられます)。
3. **Oral Session** の場合、各発表の開始・終了時刻は自動計算されます。セッションの開始時刻を起点に、各投稿の発表カテゴリ(General/Invited)と、設定ページ(3章)で指定した時間(分)をもとに、順番に積み上げて計算されます。発表がセッションの終了時刻を超過する場合は警告が表示されるので、セッション時間を延長するか、発表を別セッションに移してください。
4. **Remove** — セッションから投稿を外します。
5. **Export CSV** — 計算済みの発表時刻も含め、プログラム全体をCSV(表計算ソフト用)としてダウンロードします。
6. **View Public Page** — 閲覧専用のプログラムページ(`/program`)を開きます。プログラムは最終的に学会の公式サイトで公開される予定のため、現時点ではこのシステム上ではChairのみ閲覧可能です。

## 8. 通知メール一覧

| きっかけ | 送信先 | 自動送信されるか |
|---|---|---|
| 投稿者が投稿 | 投稿者 | される(即時) |
| 査読者アサイン | 査読者 | されない — Pending Reviewer Notificationsから手動送信(5章) |
| 査読リマインダー | 未査読の査読者 | されない — Send Remindersで手動送信(5章) |
| 採否確定 | 投稿者 | されない — Decisionsページから手動送信(6章) |

## 9. セキュリティに関する補足

- サインインメールの送信には、悪用防止のためレート制限がかかっています(同一メールアドレスへは1分に1回まで、同一送信元IPからは10分に5回まで)。
- `/admin`配下の操作、投稿の削除、プログラムの閲覧はいずれもChairロールを持つアカウントのみ可能です。
